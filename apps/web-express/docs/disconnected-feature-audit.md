# Disconnected-feature audit — 13 October 2026

## Scope and method

Source audit of `apps/web-express` (views, client controllers, routes and persistence), `apps/web` (pages, components and browser libraries), `apps/mobile` (all screens and libraries), and shared Supabase authentication templates, submission/notification functions and relevant policies. Each finding below traces a displayed promise to its handler and its persistence or verification path. This is not a live production acceptance test.

The Express delegated-event scan found no missing action bindings or missing `sf*` function definitions. A placeholder `href="#"` in the detail drawer is populated with a real permalink after loading, so it is not counted as broken. Digest availability switches, staged rollout controls and disabled buttons during loading have explicit operational conditions and are not counted as dead features.

## Findings

| Priority | Feature | Evidence and effect | Next action |
| --- | --- | --- | --- |
| High | Password-reset email code | All apps displayed a recovery code without calling verifyOtp. The Express app now provides /auth/recovery and verifies email + code with type recovery before showing the new-password form. Sources: `apps/web-express/src/client/auth-callback.ts:59`; `supabase/templates/recovery.html:84` | Implemented in this change; requires Express deployment. |
| High | Express display-name setting | The UI says the name is shown on posts and comments, but Save only writes sf_display_name to localStorage. No profile update request is made. Server-rendered identities still come from profiles/session. Sources: `apps/web-express/src/client/profile.ts:39`; `apps/web-express/views/profile.eta:124` | Connect Save to a validated account-profile update; make guest/device-only settings explicit. |
| High | Express email-notification toggle | Save only writes sf_email_notifs to browser storage. Nothing outside this settings script reads that key, while review/comment delivery checks profiles.email_notifications_enabled. The UI can say saved without changing delivery consent. Sources: `apps/web-express/src/client/profile.ts:41`; `supabase/functions/_shared/notifications.ts:162` | Save the account preference server-side and hydrate from it; keep weekly-digest consent separate. |
| High | Anonymous-by-default preference | Express stores sf_anon_default but submission code never reads it. The older Next app stores sf_anon_pref but its submit panel initializes isAnonymous independently. Both settings can be changed without affecting a new submission. Sources: `apps/web-express/src/client/profile.ts:40`; `apps/web-express/views/partials/submit-panel.eta:257`; `apps/web/components/submit-idea-panel.tsx:50` | Hydrate fresh submission defaults from the saved preference; never overwrite an existing draft. |
| High | Express Shared and Supported activity tabs | Both panes contain an empty state and permanently hidden grid. profile.ts only changes which pane is visible; it never loads/render activity rows. Supported counts read sf_voted while voting writes sf_voted_ideas, so even the local count is disconnected. Sources: `apps/web-express/views/profile.eta:313`; `apps/web-express/src/client/profile.ts:71`; `apps/web-express/src/client/feed.ts:113` | Load real activity and correct the storage contract, or remove these tabs and counts until implemented. |
| Medium | Express saved ideas versus profile bookmarks | The feed saves IDs in sf_saved_ideas and explicitly labels them device-only. The profile Bookmarks pane queries the account bookmarks table. Saving in the feed cannot populate that pane. An account bookmark API already exists but the feed does not call it. Sources: `apps/web-express/src/client/feed.ts:139`; `apps/web-express/src/lib/data.ts:257`; `apps/web-express/src/routes/api.ts:318` | Define account bookmarks for signed-in users and device bookmarks for guests, and expose each list clearly. |
| High | Older Next app offline auto-send promise | The submit panel writes a Dexie draft and promises it will send automatically when online. queuedDrafts has no production caller; the online listener only updates a badge. No sender or queue-management screen drains those records. Sources: `apps/web/components/submit-idea-panel.tsx:161`; `apps/web/lib/offline-queue.ts:13`; `apps/web/components/submit-idea-panel.tsx:81` | Add an explicit queue/recovery workflow with safe retries, or stop offering offline submission and automatic delivery. |
| High | Older Next app PKCE callback | Its callback route redirects immediately and omits code and sb_flow_id from the destination. The comment promises the browser will pick up recovery/auth tokens, but query credentials are discarded before exchange. This is separate from the Express callback fixed previously. Sources: `apps/web/app/auth/callback/route.ts:14` | Replace the redirect-only route with a browser callback that exchanges credentials and distinguishes recovery. |
| Medium | Older Next app profile Save success | Both profile interfaces await profiles.update but ignore the returned error, then display Saved. Local writes can also throw before clearing the saving state. This creates a false success path. Sources: `apps/web/components/profile-dashboard.tsx:227`; `apps/web/components/profile-panel.tsx:73` | Handle storage and database errors; show success only for confirmed persistence. |
| Medium | Other authentication-email codes | Confirmation, magic-link, invitation and email-change templates print codes, but there is no corresponding redemption UI or verifyOtp call for these types. Magic-link copy specifically advertises code login. The new reset-code page intentionally accepts recovery codes only. Sources: `supabase/templates/confirmation.html:84`; `supabase/templates/magic_link.html:81`; `supabase/templates/invite.html:88`; `supabase/templates/email_change.html:84` | Either build the matching verification flows or remove unused code blocks while retaining working links. |
| Medium | Mobile named submissions and push registration | The mobile submit switch allows account-linked submission, but the three mobile screens offer no sign-in/session-establishment flow. The backend rejects named feedback without a user. Push registration also returns when no session exists, so a fresh installation cannot complete these account-dependent paths. Sources: `apps/mobile/app/submit.tsx:167`; `supabase/functions/submit-feedback/index.ts:22`; `apps/mobile/lib/notifications.ts:63` | Add mobile authentication and retry push registration after sign-in, or constrain the mobile UI to supported guest features. |
| Low | Mobile Online badge | The submission screen always displays Online, without observing connection state. It can report online while submission is impossible offline. Sources: `apps/mobile/app/submit.tsx:110` | Observe connectivity or remove the unconditional status claim. |
| Low | Express Profile Settings shortcut | The link points to #settings but no element in that template has this ID. The actual panel ID is prof-settings-panel. Sources: `apps/web-express/views/profile.eta:81`; `apps/web-express/views/profile.eta:94` | Update the anchor to the actual panel and open its mobile accordion. |

## Recommended order

1. Deploy the reset-code entry flow implemented here.
2. Repair Express profile saves and the ignored submission-default preference.
3. Repair activity/bookmark lists so counts and empty states reflect actual behavior.
4. Fix the older Next app callback and offline delivery claim before using that frontend in production.
5. Resolve the remaining email-code promises and mobile account-dependent features.

Only the Express recovery-code flow and its email instructions are implemented in this audit change. The other rows remain open findings; they have not been silently removed or advertised as fixed. Hosted Supabase email content must be published separately to show the new instructions, while existing reset codes can be used on the new page after the Express app deploys.
